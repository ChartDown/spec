# Contributing to ChartDown

Thanks for helping shape ChartDown.

## How changes happen

ChartDown follows spec-driven development: **the spec changes first, code second.**

1. **Open an issue** describing the problem or idea, with a short example of the
   ChartDown text you want to write.
2. **Discuss** the syntax in the issue before writing code.
3. **Send a pull request** that updates `SPEC.md`, adds or updates an example in
   `examples/`, and, if needed, updates the reference playground.
4. Add a line to `CHANGELOG.md`.

## Guidelines

- Keep the syntax easy to type and easy to read as plain text.
- Never break existing charts without a version bump and a changelog entry.
- Examples must be original or public domain. Do not add copyrighted lyrics or
  arrangements.
- By contributing, you agree that your contributions to the spec, guides and
  examples are released under CC0 1.0, and contributions to the code under MIT.
